# 标签注册表数据模型

本文说明 `registry/` 下 JSON 的结构、合并顺序以及歧义 Tag 的建模方式。Registry **正文为英文**（`name`、`description`、枚举标签等）；UI 多语言不在本库范围内。

完整英文版：[../en/tag-registry-data-model.md](../en/tag-registry-data-model.md)

## 文件布局

| 文件 | 作用 |
|------|------|
| `emv.json` | EMV 基线（Book 3 Annex A 等） |
| `contactless-entry-point.json` | 非接 Entry Point overlay（Book B Annex A Table A-1） |
| `visa.json` | Visa overlay（VCPS） |
| `upi.json` | 银联 overlay（Q/CUP 045.5 第 5 部分） |
| `manifest.json` | `base` + 各 scheme 的 overlay 文件顺序 |

Scheme `S` 的加载顺序：**`base`**，再按 **`overlays[S]`** 从左到右。后加载文件中的同 hex Tag **覆盖** 扁平 map 中的条目；覆盖事件以 info 级别记录。

不存在 `metadata.priority`；优先级仅由 manifest 中的文件顺序决定。

## JSON 结构

每个 registry 文件：

```json
{
  "metadata": {
    "scheme": "EMV",
    "spec": {
      "document": "EMV_v4.4_Book_3_Application_Specification.pdf",
      "version": "4.4",
      "sections": ["Annex A", "Annex G"]
    },
    "extends": null,
    "generated": "2026-10-27"
  },
  "tags": [ … ],
  "annex": { "named_tags": [ … ] }
}
```

Schema：[`registry/tag-registry.schema.json`](../../registry/tag-registry.schema.json)

### 运行时字段 vs 文档字段

| 字段 | 运行时加载 | 说明 |
|------|------------|------|
| `tag`, `name`, `type`, `format`, `length`, `source`, `scheme`/`kernel`, `template`, `bitFields`, `enumMap` | 是 | `kernel` 为 `scheme` 别名 |
| `refs`, `disambiguation`, `variants`, `semanticPending` | 部分 | `variants` 在扁平 map 中仅保留**第一个** variant；单 Tag 的 `refs` 可选，默认出处为 **`metadata.spec`** |
| `annex.named_tags` | 否 | 非 hex 的 Annex 名称，不在 hex map 中 |

## 类型与 format 约定

- JSON 中的 **`N/A`** 加载时规范为 **`BINARY`**。
- **`BOOLEAN`** 位子规则：JSON 存为 `BOOLEAN`；加载时规范为 **`ENUM`**，`enumMap` 为 `{ "0": "false", "1": "true" }`。
- **`BITFIELD`** 的 `bitFields[].position`：从值**首字节最高位（EMV b8）**起算的 0 基位索引，逐位向低位并延续到后续字节；表格/CLI 中的 bit 编号与 EMV 表一致（字节内 `bit N` = `8 - (position mod 8)`）。
- **`CERTIFICATE`** 等解析器暂不支持的 Annex 标签 → **`BINARY`**。

## 歧义分类

| 类别 | 示例 | 本阶段 |
|------|------|--------|
| **A. 全局 EMV** | `9F02`, `95` | 仅在 `emv.json` |
| **B. Scheme 私有 Tag** | 专有 `DFxx` | 仅在 overlay |
| **C. 同 Tag、scheme 差异** | `9F66` | overlay 在 base 之后整 Tag 替换 |
| **D. EMV 上下文相关** | `DF50` 在不同 template 下 | **`variants[]`**；运行时取**第一个** variant；validate 报告多 variant |
| **E. 仅 Annex 名称** | `Enciphered_PIN_Data` | `annex.named_tags`，不进 hex map |

### `variants[]`

同一 hex 多种 EMV 含义时，在 `emv.json` 中使用 `variants[]`；详见英文版示例与 [设计文档.md](设计文档.md)。

后续计划：`getTagInfo(tag, parentStack)` 按上下文选 variant；当前未实现。

## API

- **`TLVParser::loadTagRegistry(manifestPath, scheme)`** — 应用侧推荐入口。
- **`TagRegistry::loadManifest`** — 库内部；按 manifest 合并。
- **`validateAllSchemes` / `mergeSchemeToFile`** — 见 `emvparse/tag_registry_ops.h` 与 CLI `emvparse registry …`。

## 工具

- `emvparse registry validate [--manifest path]` — hex、ENUM/BITFIELD、variant 告警
- `emvparse registry merge --scheme Visa -o out.json` — 导出合并后的 JSON
