# emvparse CLI 指南

## 安装

从 [GitHub Releases](https://github.com/idealzouhu/emvparse/releases) 下载对应平台的压缩包并解压。请保留目录结构：

- **Windows**：`bin/emvparse.exe` 与 `bin/emvparse.dll` 须在同一目录。
- **Linux**：`bin/emvparse` 通过 RPATH 加载 `../lib/libemvparse.so`。

开发构建未 `install` 时，可直接运行 `build/bin/Release/emvparse`（或 `build/bin/emvparse`）；CLI 会向上搜索源码树中的 `registry/manifest.json`。

## 子命令

### `parse`

将十六进制输入解析并输出：默认 **JSON** 到 stdout，也可选 **table**（**纯文本可读布局**，不一定是统一表格：TLV 为列对齐，C-APDU 为字段块，R-APDU 为状态行 + TLV）；**html** 写入文件（默认 `report.html`）。默认 **自动识别** 纯 BER-TLV、ISO 7816 **C-APDU** 或 **R-APDU**（响应体 + 状态字）。

```bash
emvparse parse 9F33020141 --scheme EMV
emvparse parse --file capture.hex --scheme Visa
echo 9F33020141 | emvparse parse -
emvparse parse 80A8000002830000 --format json
emvparse parse 00B2021400 --format table
emvparse parse 770E8202198094081001020120010300 --format table --semantic active
emvparse parse 770E8202198094081001020120010300 --format html
emvparse parse --file capture.hex --format html -o capture.html
```

- 十六进制可含空格；可选 `0x` 前缀。
- `--format`：`json`（默认）、`table`（stdout 纯文本，版式随输入类型变化）、`html`（写文件，不写 stdout）。
- `--output` / `-o`：仅 **html**；输出路径，`-` 表示 stdout。
- `--semantic`：`active`（默认）或 `full`，**仅对 `--format table` 生效**；JSON 不受此选项影响。
- `--input`：`auto`（默认）、`tlv`、`capdu`、`rapdu`；强制输入类型。`auto` 时依次尝试 C-APDU、R-APDU（体 + SW）、否则按 TLV。
- `--scheme`：`EMV`（默认）、`Visa`、`UPI`。
- `--registry <path>`：manifest 文件或 registry 目录（`--manifest` 为别名）。

**HTML**：页面内嵌完整语义，打开时默认只显示摘要（类似 table 的 active）；点击值列中的 **Details** 可展开/收起全部位域行（未置位行为灰色）。折叠行为与 `--semantic` 无关。

### `script`

解析**交易脚本** JSON：按顺序列出每步 **C-APDU** 与 **R-APDU**（仅 hex）。程序自动推导步骤标题、从响应中累积 **PDOL/CDOL/DDOL**、在已知 DOL 时切分 GPO / GENERATE AC 命令数据，并在每步响应与命令配对时展开 R-APDU **Format 1**（tag `80`）。

```bash
emvparse script --file txn.json --format table
emvparse script --file txn.json --format table --semantic full
emvparse script --file txn.json --format json
emvparse script --file txn.json --format html -o txn.html
```

脚本格式（**version 1**）：必填 `version`、`steps[]`，每步必填 `capdu`、`rapdu`。可选 `title`（备注）、`scheme`（覆盖 CLI `--scheme`）。Schema：[registry/transaction-script.schema.json](../../registry/transaction-script.schema.json)；示例：[docs/examples/transaction-script-v1.json](../examples/transaction-script-v1.json)。

- `--format`：`json`（默认）、`table`（stdout 逐步 Command/Send/Response）、`html`（写文件，`-o` 默认 `<脚本名>.html`）。
- `--output` / `-o`：仅 **html**。
- `--semantic`：仅 **table** 生效。
- `--scheme`、`--registry`：与 `parse` 相同。

### `tag-info`

输出单个 Tag 在 registry 中的元数据 JSON。

```bash
emvparse tag-info 9F33 --scheme EMV
```

### `registry validate`

校验 manifest 下 EMV / Visa / UPI 三套 registry。

```bash
emvparse registry validate
```

### `registry merge`

将某 scheme 合并后的 tag 列表写入 JSON 文件（失败时不写部分文件）。

```bash
emvparse registry merge --scheme EMV --output merged-emv.json
```

## Manifest 查找顺序

1. `--registry` / `--manifest`
2. 环境变量 `EMVPARSE_REGISTRY`（与 `--registry` 相同）
3. 相对可执行文件：`../share/emvparse/tag-registry/manifest.json`、`tag-registry/manifest.json`
4. 安装前缀（编译期默认路径）
5. 自可执行文件向上搜索 `registry/manifest.json`

## 环境变量

| 变量 | 说明 |
|------|------|
| `EMVPARSE_REGISTRY` | 与 `--registry`：manifest 或含 `manifest.json` 的目录 |

## 退出码

| 码 | 含义 |
|----|------|
| 0 | 成功 |
| 1 | 用法 / 参数错误 |
| 2 | Registry 加载失败 |
| 3 | 解析失败（非法 hex） |

## 全局选项

- `emvparse --version` / `-V`：与 CMake `project(emvparse VERSION …)` 一致。
- `emvparse --help` / `-h`；子命令：`emvparse parse --help` 等。
